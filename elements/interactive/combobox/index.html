Combobox

Das Schwierige ist nicht das Dropdown. Das Schwierige ist zu wissen, welcher Zustand gerade wahr ist.

Während du tippst, kann ein Vorschlag aktiv sein, ohne bereits übernommen zu sein. Genau dort beginnt der Vertrag einer echten Combobox.

01 · Zustand sehen

Query ≠ Active Option ≠ Selected Value

Tippe, navigiere mit ↑/↓ und bestätige mit Enter. Der DOM-Fokus bleibt im Eingabefeld; rechts siehst du, welche Zustände sich tatsächlich ändern.

Try “r”, then Arrow Down. Escape closes without committing.

    Ein sichtbarer Vorschlag ist noch keine Auswahl.

    Der Aha-Punkt: Pfeilnavigation darf einen Vorschlag hervorheben, ohne ihn heimlich zum Feldwert zu machen.

    02 · Erst das richtige Control wählen

    Select, datalist oder Combobox?

    Hier trägt der Alternativenvergleich: Die drei Controls sehen ähnlich aus, übernehmen aber sehr unterschiedliche Verträge.

    Native first

    <select>

    Gewinnt, wenn: gültige Werte feststehen und genau einer davon gewählt werden soll.

    Browser und Betriebssystem übernehmen den größten Teil von Semantik, Tastatur und Mobile-Verhalten.

    Simple suggestions

    <datalist>

    Kann reichen, wenn: freie Eingabe gültig bleibt und einfache Vorschläge genügen.

    Aber: aktuelle Styling-, Browser- und Accessibility-Grenzen müssen zum Zielkontext passen.

    Custom contract

    Combobox

    Wird begründbar, wenn: Query-Filterung, aktive Vorschläge, Value Policy oder kontrollierte Popup-Semantik wirklich gebraucht werden.

    „Wir wollen das Dropdown schöner“ reicht nicht.

    Decision Gate

    Brauchst du wirklich den zusätzlichen Zustand?

    1. Ist die Wertemenge geschlossen und bekannt? → zuerst <select>.
    2. Bleibt freie Eingabe gültig und reichen simple Vorschläge? → <datalist> prüfen und real testen.
    3. Musst du Query, aktive Option und committed Value getrennt kontrollieren? → Combobox wird fachlich plausibel.

    03 · Drei Value-Verträge

    Showcase

    Alle Beispiele verwenden List Autocomplete mit manueller Auswahl. Unterschiede entstehen aus dem Daten- und Value-Vertrag, nicht aus drei Skins.

    • Free Text Suggestions – Vorschläge helfen, beliebiger Text bleibt gültig.
    • Restricted Selection – ein Listenwert muss explizit übernommen werden.
    • Rich Suggestions – Optionen zeigen Zusatzinfo, bleiben aber je ein einziger auswählbarer Wert.

    04 · Unsichtbarer Vertrag

    DOM-Fokus bleibt im Input.

    ↓

    Active Option

    Der sichtbare Fokus wandert durch die Vorschläge. DOM-Fokus bleibt im Eingabefeld; aria-activedescendant zeigt auf die aktive Option.

    Enter

    Commit

    Erst jetzt wird die aktive Option zum übernommenen Wert – sofern die Variante diesen Commit-Pfad definiert.

    Esc

    Dismiss

    Der Popup schließt, ohne die aktive Option stillschweigend zu übernehmen.

    Tab

    Weiter

    Tab bleibt normale Seitenfokusnavigation. Die Combobox erfindet keinen eigenen Tab-Mechanismus.

    Home, End, Delete, Cursorbewegung und Zeichen-Eingabe bleiben Textbearbeitung. Ein Custom Widget darf nicht aus Versehen die Fähigkeiten des nativen Inputs zerstören.

    05 · Benennen

    Anatomie und Zustände

    input[role=combobox]

    Besitzt DOM-Fokus, Query und den zugänglichen Namen.

    listbox

    Der Popup mit den aktuell verfügbaren Kandidaten.

    option

    Ein Kandidat. In Rich Suggestions darf er Zusatztext, aber keine eigene Unterinteraktion enthalten.

    aria-expanded

    Spiegelt Popup-Sichtbarkeit.

    aria-controls

    Verknüpft Input und Popup.

    aria-activedescendant

    Zeigt auf die visuell aktive Option, während DOM-Fokus im Input bleibt.

    06 · Selbst prüfen

    Review it yourself

    • Kannst du Query, aktive Option und übernommenen Wert im Code klar voneinander unterscheiden?
    • Bleibt DOM-Fokus im Input, während ↑/↓ durch Vorschläge navigiert?
    • Zeigt aria-activedescendant nur auf eine existierende sichtbare Option?
    • Wird die aktive Option bei langer Liste sichtbar gescrollt?
    • Übernimmt Enter gezielt, während Escape nur schließt?
    • Funktionieren native Text-Editing-Tasten weiterhin normal?
    • Erzwingt Restricted Selection tatsächlich einen gültigen Listenwert?
    • Bleibt Free Text tatsächlich frei?
    • Funktioniert das Widget bei 320 CSS px und 200 % Zoom?
